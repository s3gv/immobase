## English

ImmoBase is licensed under the **GNU Affero General Public License v3.0 or later**. Contributions are welcome, but this project asks every contributor to sign a Contributor License Agreement first. Please read the short explanation below before you open a pull request.

### Why there is a CLA

ImmoBase is developed under an open-core model. The maintainer intends to offer commercial licenses for the software alongside the AGPLv3 version.

Without a CLA that would not be legally possible: a contributor who submits code under AGPLv3 alone grants only AGPLv3 rights, and the combined work could then never be offered under any other terms. The CLA closes that gap.

### What the CLA does and does not do

**You keep the copyright in your contribution.** This is a license agreement, not a copyright assignment. You can continue to use, publish and relicense your own code anywhere else, exactly as if you had never signed.

**You grant the maintainer a broad license** — perpetual, worldwide, irrevocable, royalty-free, sublicensable and transferable — covering both copyright and patents.

**The maintainer may license your contribution under any license**, including proprietary and commercial ones.

**But the maintainer must also keep licensing it under AGPLv3.** This is a binding condition, not a courtesy. Your contribution cannot be removed from the open source version and sold exclusively. ImmoBase can grow a commercial edition; it cannot be taken closed.

The full, authoritative text is in [CLA.md](CLA.md). If anything below contradicts it, the CLA text governs.

### Signing the CLA

You do not need to print, sign or email anything.

1. Open your pull request as usual.
2. A bot will comment on it asking you to accept the CLA.
3. Reply on the pull request with exactly this sentence:

   ```
   I have read the ImmoBase Contributor License Agreement v1.0 and I hereby sign it.
   ```

4. The bot records your GitHub username, user ID, the pull request number and a timestamp in the signature register on the `cla-signatures` branch of this repository. It will not ask you again on future pull requests.

If the CLA text is ever amended in substance, its version number changes and you will be asked to accept the new version once. Signatures already recorded stay valid for the version they were given for.

### Contributing on behalf of a company

If you are contributing as part of your employment, or your employer owns the copyright in your work, your employer signs instead of you.

This project publishes no email address, so the private channel is arranged rather than advertised:

1. Open an issue titled **"Entity CLA"**, naming your company and saying that you want to contribute on its behalf. **Do not attach the signed agreement to the issue** — issues are public.
2. The maintainer replies in that issue with a private channel to send the signed document to.
3. Download [CLA-CORPORATE.md](CLA-CORPORATE.md), have an authorised signatory sign it, and send it through that channel.
4. Include the GitHub accounts that will contribute on the company's behalf. Harmony's Entity CLA covers the legal entity and its affiliates but does not itself name individuals, so this list is what lets the automation recognise those accounts.
5. The maintainer records the company in the signature register and adds those accounts to the bot's allowlist.

Send any later changes to the account list the same way.

### Contributions you do not fully own

Only submit work whose copyright you actually hold.

If a change contains code you did not write — a snippet from another project, a vendored file, generated output that carries someone else's license — **do not open a pull request for it**. Open an issue first and state where the code came from and under which license. Third-party code may still be usable, but it has to be tracked separately from your own contribution and cannot be covered by your CLA.

The same applies to code you wrote for an employer or client who owns the result.

### Code of conduct

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md).

### Security issues

Do not report vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).

### Project status

ImmoBase is being rebuilt from scratch and is not yet usable. Until the first release, external pull requests are unlikely to be merged — the architecture is still moving. Issues and discussion are welcome regardless.

## Mitwirken an ImmoBase

> **Hinweis:** Dieser deutsche Abschnitt ist eine unverbindliche Lesehilfe. Rechtlich maßgeblich ist ausschließlich der englische Vertragstext in [CLA.md](CLA.md) bzw. [CLA-CORPORATE.md](CLA-CORPORATE.md). Bei Abweichungen gilt der englische Text.

ImmoBase steht unter der **GNU Affero General Public License v3.0 oder später**. Beiträge sind willkommen — vorher muss allerdings jeder Beitragende eine Contributor License Agreement (CLA) annehmen.

### Warum es eine CLA gibt

ImmoBase wird nach einem Open-Core-Modell entwickelt. Der Projektinhaber möchte neben der AGPLv3-Fassung auch kommerzielle Lizenzen anbieten können.

Ohne CLA ginge das rechtlich nicht: Wer Code allein unter AGPLv3 einreicht, räumt auch nur AGPLv3-Rechte ein — das Gesamtwerk ließe sich dann nie unter anderen Bedingungen anbieten. Genau diese Lücke schließt die CLA.

### Was die CLA bedeutet

**Dein Urheberrecht bleibt bei dir.** Es handelt sich um eine Lizenzvereinbarung, nicht um eine Übertragung des Urheberrechts. Du kannst deinen eigenen Code weiterhin überall sonst verwenden, veröffentlichen und anders lizenzieren — genau so, als hättest du nie unterschrieben.

**Du räumst dem Projektinhaber eine weitgehende Lizenz ein** — zeitlich unbegrenzt, weltweit, unwiderruflich, unentgeltlich, unterlizenzierbar und übertragbar, für Urheberrecht und Patente.

**Der Projektinhaber darf deinen Beitrag unter jeder Lizenz weitergeben**, auch unter proprietären und kommerziellen.

**Er muss ihn aber weiterhin auch unter AGPLv3 anbieten.** Das ist eine verbindliche Bedingung, kein Entgegenkommen. Dein Beitrag kann nicht aus der Open-Source-Fassung herausgenommen und ausschließlich verkauft werden. ImmoBase kann eine kommerzielle Edition bekommen — geschlossen werden kann es nicht.

### CLA annehmen

Du musst nichts ausdrucken, unterschreiben oder per Mail schicken.

1. Pull Request wie gewohnt öffnen.
2. Ein Bot kommentiert und bittet um Annahme der CLA.
3. Antworte im Pull Request mit exakt diesem Satz:

   ```
   I have read the ImmoBase Contributor License Agreement v1.0 and I hereby sign it.
   ```

   Der Satz muss auf Englisch stehen, weil er sich auf den maßgeblichen englischen Vertragstext bezieht.

4. Der Bot trägt GitHub-Benutzername, Benutzer-ID, PR-Nummer und Zeitstempel in das Signaturregister auf dem Branch `cla-signatures` ein. Bei späteren Pull Requests wirst du nicht erneut gefragt.

Wird der CLA-Text inhaltlich geändert, ändert sich seine Versionsnummer und du wirst einmalig um Annahme der neuen Fassung gebeten. Bereits erfasste Signaturen bleiben für die Fassung gültig, für die sie abgegeben wurden.

### Beiträge im Namen einer Firma

Wenn du im Rahmen deiner Anstellung beiträgst oder dein Arbeitgeber die Rechte an deiner Arbeit hält, unterschreibt der Arbeitgeber statt dir — siehe [CLA-CORPORATE.md](CLA-CORPORATE.md).

Das Projekt veröffentlicht keine E-Mail-Adresse. Öffne stattdessen ein Issue mit dem Titel **„Entity CLA"** und nenne die Firma; der Projektinhaber antwortet dort mit einem privaten Kanal für das unterschriebene Dokument. **Häng den unterschriebenen Vertrag nicht ans Issue an** — Issues sind öffentlich. Details im englischen Abschnitt oben.

### Beiträge, die dir nicht vollständig gehören

Reiche nur Arbeit ein, deren Urheberrecht du tatsächlich hältst.

Enthält eine Änderung fremden Code — ein Schnipsel aus einem anderen Projekt, eine mitgelieferte Datei, generierte Ausgabe unter fremder Lizenz — **öffne dafür keinen Pull Request**. Melde dich zuerst über ein Issue und nenne Herkunft und Lizenz. Fremder Code ist unter Umständen trotzdem verwendbar, muss aber getrennt von deinem eigenen Beitrag nachgehalten werden und wird von deiner CLA nicht abgedeckt.

Dasselbe gilt für Code, den du für einen Arbeitgeber oder Kunden geschrieben hast, dem das Ergebnis gehört.

### Projektstatus

ImmoBase wird gerade von Grund auf neu gebaut und ist noch nicht benutzbar. Bis zum ersten Release werden externe Pull Requests eher nicht gemergt — die Architektur bewegt sich noch. Issues und Diskussion sind trotzdem willkommen.
